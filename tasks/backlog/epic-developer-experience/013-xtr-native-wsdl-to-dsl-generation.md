# 013 — XTR-native WSDL → DSL generation (folder drop + gated admin endpoint)

## Filed

2026-07-28 initial filing; revised across the same day + 2026-07-29
into four shapes as Rainer clarified intent:
  * v1 (dropped): CLI scaffold — one-shot dev tool.
  * v2 (dropped): boot-time runtime auto-generation with cache
    + refresh — too much magic, too much cold-start latency.
  * v3 (dropped): CI-driven pre-generation with drift-detect —
    version-controlled but operator-hostile (CI setup + PR
    cycle for every new service).
  * v4 (this): **XTR-native**. XTR itself ingests WSDLs from a
    watched folder OR a gated admin endpoint, generates DSLs
    to disk (same slot as hand-written), and the existing
    loader picks them up. Closest to how Traefik/Kong/NGINX-
    Proxy-Manager handle service definitions.

## Severity

**High** for adoption. Zero setup friction: drop a WSDL file →
restart → endpoints exist. No CI. No git dance. Operators can
still commit generated DSLs for reproducibility if they want,
but that's optional.

## Design

### 1. Config

Two new `xtr.yaml` sections, both optional and off-by-default:

```yaml
# WSDL folder-drop. Operator places WSDL files here; XTR
# generates DSLs to `dsl_path:` at boot. Absent = feature off.
wsdl_watch_dir: /app/wsdl

# Gated admin endpoints. Off by default; must be explicitly
# enabled AND have an API key configured. Both required.
admin:
  enabled: false
  api_key_env: XTR_ADMIN_API_KEY
  # Optional additional restriction on POST /admin/wsdl-from-url:
  wsdl_url_allow_hosts: []          # empty = any host
```

Startup refuses to boot if `admin.enabled: true` but the API-key
env var is unset (same fail-fast posture as
`security_server.keystore_password_env`).

### 2. Folder-drop convention

Layout inside `wsdl_watch_dir`:

```
<wsdl_watch_dir>/
├── ar/                     # group name = subdir name
│   └── ariregister.wsdl    # any .wsdl file in the subdir
└── xroad/
    └── meta.wsdl
```

Boot-time flow per WSDL:

1. Parse WSDL via a new `src/wsdl/` module (see §5).
2. Emit one DSL per `wsdl:operation` at
   `<dsl_path>/<group>/<operation>.yml`.
3. Each generated file leads with a marker header:
   ```yaml
   # GENERATED FROM wsdl/<group>/<file>.wsdl
   # Do not edit — regenerate by replacing the source WSDL
   # and restarting XTR. Delete this header line to convert
   # the file into a hand-written override.
   ```
4. Collision rules on the DSL file:
   - File exists AND has the marker → overwrite (safe, we own
     it).
   - File exists WITHOUT the marker → SKIP with WARN
     ("hand-written override wins"). Operator's edits stand.
   - File doesn't exist → write.

Existing `loader::load_all` then picks up every generated +
hand-written `.yml` unchanged. Zero changes to loader
behaviour.

### 3. Admin endpoint (gated URL ingestion)

Mounted only when `admin.enabled: true`:

```
POST /admin/wsdl-from-url
Authorization: Bearer <XTR_ADMIN_API_KEY value>
Content-Type: application/json

{ "url": "https://ariregxmlv6.rik.ee/?wsdl", "group": "ar" }
```

Handler:

1. Verify `Authorization` header matches
   `env[cfg.admin.api_key_env]`. Constant-time compare. Missing
   or wrong → 401 with structured error.
2. If `wsdl_url_allow_hosts` is non-empty, verify the URL's host
   is in the list. Not in list → 403 + structured error.
3. Fetch the URL via a new `reqwest::Client` with a hard
   `limits.max_response_bytes` cap (reuses the existing
   size-cap primitive from task 011).
4. Basic sanity: response Content-Type suggests XML, body
   parses as WSDL. Failure → 400 with structured error.
5. Write bytes to
   `<wsdl_watch_dir>/<group>/<sha256[:12]>-<hostname>.wsdl`.
6. Regenerate the DSLs for that group (see §4 — hot vs
   cold).
7. Return `202 Accepted` (v1 — needs restart) or `200 OK`
   (v2 — hot-reload landed).

Requiring `wsdl_watch_dir` to be set alongside — the admin
endpoint writes to it. If `wsdl_watch_dir` is absent, the admin
endpoint 500s with a clear error.

### 4. Reload posture

**v1 (this task):** boot-time only. Operator drops WSDL / hits
admin endpoint → restart XTR → new endpoints live.

**v2 (follow-up task):** file-watcher on `wsdl_watch_dir` via
`notify` crate. On WSDL change → regenerate DSLs → hot-swap
`ServiceMap` atomically. Also add a "generated by our own
generator" dedupe check so we don't loop on our own writes.

v1 is a strict subset of v2's design — v2 adds the watcher on
top without changing v1's data flow.

### 5. WSDL parser

New crate module `src/wsdl/` (not a separate crate — it's
runtime code now, unlike v3's plan).

Uses existing `quick-xml` dep — no new dependencies. Parses
the SOAP-1.1-over-HTTP subset X-Road uses:

- `wsdl:definitions` root
- `wsdl:types` → `xsd:schema` → element definitions
- `wsdl:message` → parts referencing types
- `wsdl:portType` → operations mapping input/output messages
- `wsdl:binding` → SOAP-over-HTTP binding, `soap:operation`
  soapAction
- `wsdl:service` → `soap:address location="..."` for the
  target URL

Unsupported constructs (WSDL 2.0, RPC/encoded, MIME
attachments, WS-Addressing headers beyond the X-Road ones) →
bail with a clear error naming the construct + the WSDL file.
Never emit a wrong DSL silently.

X-Road-specific detail: when the WSDL's target is under an
X-Road subsystem (config's `security_server` is present AND
the WSDL was fetched via `wsdl-from-url` with an
`xroad_target` in the request body), the generator injects the
standard X-Road header block (`{{{generate.client}}}`,
`{{generate.uuid}}`, `{{generate.protocol_version}}`,
`<xroad:service>` with the target identity) into the envelope.

### 6. Deterministic output

Generated YAML must be byte-stable across runs (same WSDL →
same DSL bytes):
- Fields in fixed order: `# marker`, `params:`, `service:`,
  `method:`, `envelope:`.
- Params sorted alphabetically OR in WSDL declaration order
  (pick one and stick with it — I'd pick declaration order,
  matches what a hand-written author would do).
- Handlebars whitespace normalized.
- Trailing newline, LF line endings.

Enables the operator to `git diff` two runs and see only what
actually changed in the WSDL.

## Acceptance

- Configuring `wsdl_watch_dir` alone (no admin) works: drop a
  WSDL, restart, endpoints appear.
- Configuring `admin.enabled: true` without an API key env
  var → startup refuses with a clear error.
- Configuring `admin.enabled: true` WITH the env var mounts
  `POST /admin/wsdl-from-url`; missing/wrong Authorization →
  401; wrong host (when allow-list set) → 403; success writes
  to `wsdl_watch_dir` and returns 202.
- Generated DSLs land at
  `<dsl_path>/<group>/<operation>.yml` with the marker
  header.
- Hand-written DSLs (no marker) survive when a WSDL would
  overwrite the same path — WARN log identifies the
  shadowing.
- Existing tests unchanged (loader/handlebars/executor path
  is untouched).
- Round-trip test: drop
  `tests/fixtures/wsdl/ariregister.wsdl` (a captured copy of
  the public WSDL) into a temp `wsdl_watch_dir`; boot XTR;
  assert the 4 generated `/ar/*` endpoints exist and their
  envelopes contain the expected `<prod:*>` operation
  elements.
- Admin endpoint fetch: mock upstream serves a WSDL; hit
  `/admin/wsdl-from-url` with valid auth; assert the WSDL
  lands under `wsdl_watch_dir` and (after restart) the
  endpoints are live.
- New `book/src/ops/wsdl-ingestion.md` chapter documents
  folder layout, marker semantics, override rules, admin
  endpoint auth, and host allow-list.
- `book/src/dsl/adding-a-service.md` "Coming soon" section
  becomes past-tense: XTR now generates DSLs from WSDLs; the
  hand-written path (this chapter) is the override
  mechanism.
- `SUMMARY.md` gains the wsdl-ingestion chapter link.

## Dependencies

- None hard. `notify` for v2 hot-reload but not v1.
- Task 007 (mock SS harness) would let the X-Road-target
  round-trip test run in CI without a real SS. Not required
  for v1 (the public-WSDL round-trip works with an ad-hoc
  axum test upstream, which is what tests/it_end_to_end.rs
  already uses).

## Non-scope

- **Hot-reload on WSDL change.** v2 follow-up. v1 requires
  restart.
- **Multi-WSDL merging within a group.** For v1: one `.wsdl`
  file per group, filename ignored. Multiple WSDLs in the
  same group subdir → each generates independently, dupes
  cause the last-loaded to win (with WARN). Cleaner shape is
  a follow-up.
- **WSDL 2.0.** Not used in X-Road.
- **Auto-refresh from URL sources.** If operator wants that,
  they can `curl -X POST /admin/wsdl-from-url` on their own
  cron.
- **Version-controlling generated DSLs.** Operator's choice —
  the marker header makes them obviously auto-generated.
  Committing captures the current WSDL's state; not
  committing keeps the WSDL as the source of truth. Both
  workflows work.

## Risks

- **SSRF via admin endpoint**. Mitigation: (a) endpoint
  off-by-default, (b) API-key gate, (c) optional
  `wsdl_url_allow_hosts` allow-list, (d) response-size cap
  (reuses task 011's primitive), (e) startup refuses if
  `admin.enabled: true` without an API-key env var.
- **Generator determinism bugs**. Round-trip test asserts
  byte-equal output across two consecutive runs in CI.
- **WSDL parsing surprises in the wild**. Bail-out-on-
  unsupported-construct posture — never emit a wrong DSL.
  Operator overrides with hand-written for unsupported
  cases.
- **Filesystem races** (generator writing while loader
  reading). v1 sequences them strictly: generate → then
  load. No concurrent access at boot. v2's hot-reload needs
  atomic file replace (`write to .tmp → rename`).
