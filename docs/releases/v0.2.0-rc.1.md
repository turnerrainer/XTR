# Release gate — `v0.2.0-rc.1` (hotfix)

**Merging this PR** approves the release manager to push the
`v0.2.0-rc.1` git tag on `origin`. Tag push triggers
`.github/workflows/publish.yml` → build + smoke +
cosign-sign + push to Docker Hub + GHCR.

## Why

`0.2.0-rc` shipped with a Dockerfile ENTRYPOINT/CMD shape
that broke every subcommand invocation. The doctor recipe
promised in `MIGRATION.md`:

```bash
docker run --rm -v $(pwd)/xtr.yaml:/app/xtr.yaml:ro \
  turnerrainer/xtr:0.2.0-rc doctor --strict
```

…actually did:

```
[FATAL tini (7)] exec doctor failed: No such file or directory
```

Because `CMD ["/app/xtr-on-rust"]` under
`ENTRYPOINT ["/usr/bin/tini", "--"]` means the trailing
`doctor` argv REPLACES CMD, so tini tries to exec a `doctor`
binary that doesn't exist.

Discovered while local-testing the fresh `0.2.0-rc` image
end-to-end (this is exactly what a real operator would hit
on their first attempt).

## Fix

`Dockerfile`:

```diff
-ENTRYPOINT ["/usr/bin/tini", "--"]
-CMD ["/app/xtr-on-rust"]
+ENTRYPOINT ["/usr/bin/tini", "--", "/app/xtr-on-rust"]
+CMD []
```

Extra args now APPEND to the binary (`tini -- /app/xtr-on-rust doctor`).
Bare `docker run <image>` still boots the server (no argv →
server path in `main.rs::Cli::parse`).

`tests/dockerfile_entrypoint.rs` — new contract test parses
the Dockerfile and refuses any shape where ENTRYPOINT
doesn't pin the binary. Guards against this class of
regression before publish. Runs in the normal `cargo test`
gate.

## What tagging will do

`publish.yml` fires on tag push matching `v[0-9]+.[0-9]+.[0-9]+-*`.
For `v0.2.0-rc.1`, the tag suffix logic derives
`SUFFIX_TYPE=rc`, so it pushes:

Registry | Tag | Effect
---|---|---
`docker.io/turnerrainer/xtr` | `:0.2.0-rc.1` | new, immutable
`docker.io/turnerrainer/xtr` | `:rc` | moves from `0.2.0-rc` → `0.2.0-rc.1`
`ghcr.io/turnerrainer/xtr` | `:0.2.0-rc.1` | new, immutable
`ghcr.io/turnerrainer/xtr` | `:rc` | moves from `0.2.0-rc` → `0.2.0-rc.1`

`:latest` and `:0.2` still not moved (pre-release rules).

## Verified locally

- `docker run -d -p 18083:8080 xtr:hotfix-test` — server boots,

- `cargo fmt --check` + `cargo clippy -D warnings` clean

## What breaks if we DON'T ship this

Anyone following the MIGRATION.md doctor recipe on `0.2.0-rc`
hits the tini FATAL and has to reverse-engineer the
workaround `docker run <image> /app/xtr-on-rust doctor`.
Bad first-touch experience; undermines the whole point of
shipping the doctor tool.

## On merge, the release manager will

1. Fast-forward `dev` locally.
2. `git tag -a v0.2.0-rc.1 -m "..." <merge-sha> && git push origin v0.2.0-rc.1`
3. Monitor `publish.yml`.
4. Verify `docker pull turnerrainer/xtr:0.2.0-rc.1` + doctor
   subcommand works via the MIGRATION.md recipe.
5. Report tag digest + registry URLs back here.

Approve + merge to proceed.
