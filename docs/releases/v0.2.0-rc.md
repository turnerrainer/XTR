# Release gate — `v0.2.0-rc`

**Merging this PR is the explicit approval** for the release
manager (Claude, per operator directive) to push the
`v0.2.0-rc` git tag on `origin`. The tag push then triggers
`.github/workflows/publish.yml` which builds, tests, and
publishes the container image to Docker Hub + GHCR.

Nothing in this file changes runtime behaviour — the version
bump landed in [PR #2](../../pull/2). This PR exists purely
as the gate.

## What tagging will do

`publish.yml` fires on tag push matching `v[0-9]+.[0-9]+.[0-9]+-*`.
For `v0.2.0-rc`, the workflow will:

1. Check out the tag (`cabd3e0` — the merge commit of PR #2).
2. Build multi-arch (`linux/amd64` + `linux/arm64`) container
   image from `Dockerfile` (Rust builder on `rust:1.88-slim`,
   runtime on `debian:13.6-slim` from merged Snyk PR #1).
3. Boot each per-arch image, poll `/health` for 90 s. If
   either fails, publish aborts before signing.
4. Push these tags to **both** `docker.io/turnerrainer/xtr`
   and `ghcr.io/turnerrainer/xtr`:
   - `0.2.0-rc` (immutable, new)
   - `rc` (moves from `0.1.0-rc.2` → `0.2.0-rc`)
5. Attach SPDX SBOM + in-toto provenance to the multi-arch
   manifest.
6. Cosign keyless-sign both digests via GHA OIDC.
7. Note: `latest` and `0.2` are NOT moved by a pre-release
   tag (publish.yml logic in `Compose image tags` step).

Total runtime typically ~5-8 minutes.

## What the `:rc` tag move affects downstream

Anyone pulling `turnerrainer/xtr:rc` (unversioned floating
pointer for RC watchers) will start receiving `0.2.0-rc` on
their next pull. That includes:

- The four breaking changes documented in
  [`MIGRATION.md`](../../MIGRATION.md) (SOAP fault response
  shape, `xroad_protocol_version` enum, sidecar identity
  validation, WSDL URL guard on private IPs).
- The `debian:13.6-slim` base (was `bookworm-slim`).

Anyone pinning `turnerrainer/xtr:0.1.0-rc.2` explicitly is
unaffected — that immutable tag stays at digest
`sha256:61d441d00f75` forever.

## Rollback

`0.1.0-rc.2` remains cosign-signed at digest
`sha256:61d441d00f75` on both registries. Rollback = pod-spec
image swap; no data migration (XTR is stateless).

## On merge, the release manager will

1. Fast-forward `dev` locally.
2. Run: `git tag -a v0.2.0-rc -m "..." cabd3e0 && git push origin v0.2.0-rc`
3. Monitor `publish.yml` run.
4. Verify `docker pull turnerrainer/xtr:0.2.0-rc` returns a
   working image with `/health` OK.
5. Report tag digest + registry URLs back here.

Approve + merge to proceed.
